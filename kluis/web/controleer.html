Terug naar de kluis

De belofte

Namen, adressen en contactgegevens van proefpersonen staan alleen versleuteld op jouw apparaat en, als back-up, versleuteld op de server. Ontsleutelen gebeurt alleen in jouw browser, met een sleutel die in jouw browser is gemaakt. De NeedForHeat-server, en wie hem beheert, kan de kluis niet lezen. De server kent alleen pseudoniemen: accountnummers.

Je hoeft dat niet op ons woord te geloven. Hieronder staat per bewering hoe je het nagaat, van eenvoudig naar grondig.

1. Wat er naar de server gaat

VerzoekWat gaat er heenWat komt terug
GET /api/admin/overviewnietscampagnes (namen, nummers)
POST /api/admin/campaigns/{id}/accountsalleen een aantalnieuwe accountnummers en uitnodigingslinks
GET /api/admin/campaigns/{id}/mailnietsstaat de mailfaciliteit aan, helpdeskadres
PUT /api/admin/vaults/{kluis-id}de kluis, versleuteld (age)versienummer
GET /api/admin/vaults/{kluis-id}nietsde kluis, versleuteld

Zelf zien: open de ontwikkelhulpmiddelen van je browser (F12), tab Netwerk, en werk in de kluis. Je ziet alleen deze verzoeken. Bij accounts staat in de aanvraag alleen {"count": n}; de back-up begint met age-encryption.org/v1 en is verder onleesbaar. De server weigert alles wat niet zo begint.

Afgedwongen: de pagina heeft een Content-Security-Policy (onderaan de kluis onder Wat deze pagina mag): alleen deze eigen host, geen formulieren die ergens heen gaan. De webserver van de kluis laat bovendien alleen deze vijf API-routes door. Python en de pakketten staan op dezelfde host; er wordt niets van een CDN geladen.

2. De versleuteling

  • Formaat: age v1, een open en eenvoudige standaard (X25519, ChaCha20-Poly1305, HKDF-SHA256, scrypt). Onze implementatie (kluis/src/kluis/age.py, ongeveer 300 regels) gebruikt de bibliotheek cryptography en wordt in CI getest tegen de officiële age-tool, in beide richtingen.
  • Waarom asymmetrisch: de kluis is versleuteld voor een of meer publieke sleutels (die van jou, en van collega's die je toevoegt). Toegang geven of intrekken kan zonder een gedeeld wachtwoord rond te sturen.
  • Je geheime sleutel is in je browser gemaakt. Op dit apparaat staat hij versleuteld met je wachtwoordzin (age, scrypt). De herstelsleutel heb je zelf offline bewaard. Geen van beide gaat naar de server.
  • Zelf openen, zonder de Cockpit: download de versleutelde kluis (tab Sleutels) en open hem met de standaardtools: 
    age -d -i kluis-herstelsleutel.txt kluis.age > kluis.sqlite
sqlite3 kluis.sqlite "select id, account_id, naam, email from deelnemer"
    Zo weet je ook dat je nooit vastzit aan deze software.

3. Draait hier de code die gepubliceerd is?

De kluis is een handvol statische bestanden. Elk bestand staat met grootte en SHA-256 in manifest.json, samen met de commit waaruit het is gebouwd.

  1. Broncode lezen: kluis/ in energiegedrag-cockpit. De schil (app.js) geeft alleen JSON door; alles met persoonsgegevens en sleutels gebeurt in Python (src/kluis), dat geen netwerkbibliotheek mag importeren (test test_kern.py).
  2. Herkomst van de build: GitHub Actions bouwt de kluis en ondertekent manifest.json (build provenance attestation): 
    curl -O https://kluis.energiegedrag.nl/manifest.json
gh attestation verify manifest.json --repo energiegedrag-nl/energiegedrag-cockpit
  3. Zelf bouwen en vergelijken: de build is reproduceerbaar: dezelfde commit geeft byte voor byte dezelfde bestanden. Bouw zelf en vergelijk met wat deze server uitlevert: 
    git clone https://github.com/energiegedrag-nl/energiegedrag-cockpit
cd energiegedrag-cockpit
git checkout <commit uit manifest.json>
python kluis/controleer.py https://kluis.energiegedrag.nl/
    controleer.py bouwt de kluis, haalt elk bestand van de server en meldt elk verschil.
  4. Pyodide: Python in de browser komt uit een vastgepinde Pyodide-release. De runtime wordt bij het bouwen gecontroleerd tegen kluis/pyodide-sha256.json, elk pakket tegen de hash in pyodide-lock.json, en de browser controleert de pakketten bij het laden nog eens.

4. Wat dit niet afdekt

  • Een gekraakte server kan andere code uitleveren. Dat zie je met stap 3 (controleer.py of de hashes in manifest.json), maar alleen als je kijkt. Controleer na een update, en zeker voordat je een nieuwe kluis maakt.
  • Je eigen apparaat: malware of een kwaadaardige browserextensie op je laptop kan meekijken terwijl de kluis open is. Werk op een bijgewerkt apparaat, vergrendel de kluis als je klaar bent.
  • Exports en mailconcepten (CSV, .eml) zijn niet versleuteld. Verwijder ze na gebruik.
  • Uitnodigingen per mail gaan via je eigen mailprogramma; wat je mailprovider ziet, valt buiten de kluis. De mailfaciliteit van energiegedrag.nl (als de beheerder die voor je campagne aanzet) ziet ontvanger en inhoud van wat hij verstuurt.
  • Metadata: de server ziet hoe groot de kluis is en wanneer hij verandert, en hoeveel accounts je maakt.
